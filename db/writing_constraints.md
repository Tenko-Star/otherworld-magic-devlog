# 写作约束与强制质检

本文件集中保存用户的写作要求，是写作与质检的必读规则。协作及 Git 流程见 [AGENTS.md](../AGENTS.md)。用户后续补充的写作约束继续在此更新，不仅留在聊天记录中。

## 每次写完后的必做流程

1. 每次新写、续写、改写、润色和聊天中的试写片段，完成后必须按 `novel-humanizer` 技能检查并处理，不得以篇幅短、只是初稿、已凭感觉润色或用户尚未要求检查为由跳过。写作前读取技能的 `SKILL.md`；同一上下文中已完整读取且未变化时可沿用。
2. 逐条扫描技能规则及本文件约束，标记问题的位置、原文、类型、严重程度与修改建议。对照当前正文、出场人物与场景档案、公共设定、摘要和大纲核对因果、时间、人物知情边界及技术顺序；检查前五章（不足五章则检查已有章节）的重复动作、对白、解释和收束方式。
3. 对全文进行九维深度评估，沿用技能的权重与单项合格线：逻辑性18%／85、角色一致性16%／85、世界观一致性8%／85、时代适配度14%／80、对话自然度11%／80、文学性10%／75、情感表达10%／80、节奏感9%／75、去系统化4%／90。检查章尾钩子；试写片段未覆盖章尾时明确标记不适用，不虚构章节评价。
4. 对发现的表达问题实际改写，保留原意、情节与用户约束；不能只给建议而不处理。事实或核心设定冲突需要用户决定时，说明冲突并等待决定，不擅自改设定。不要为满足技能的通用示例硬加方言、肢体反应、比喻、情节或具名配角。
5. 改写后重新检查修改处及上下文，确认问题处理结果并记录剩余问题。未解决的逻辑、世界观冲突不得标为通过；单项不达合格线或加权总分未超过85分时继续处理与复查，无法解决则如实标为待处理。不得为了过线调整评分或声称客观检测合格。
6. 报告以 JSON 存入被 Git 忽略的 `temp/quality-reports/`，采用 `novel-humanizer_<章节或sample>_<日期>_<序号>.json`，保留每轮报告。报告及其索引只保存在本地，以后不暂存、不提交、不推送；旧报告迁入该目录，不改写 Git 历史。记录检查对象及版本、采用的规则、九维评分与加权总分、严重程度排序的问题、原文与改写对照、处理状态、复查结果、适用性说明和遗留事项；以文本概括评分强弱，与可比历史报告比较趋势，无可比数据时明示。聊天试写也留报告，但不写入正式章节或当作已发生剧情；用户明确要求丢弃时按其要求处理。
7. 检查结束后，同步本次实际改动涉及的摘要、人物、场景、进度；本地报告索引也须更新，但不纳入提交。本轮提交仅包含正文及相关正式资料、规则。报告必须对应最终交付文本；之后又改正文，须重新检查并更新报告。用户尚未说完修改意见时仍只提交、不推送。

## 技能在本项目中的资料对应

- 人物、世界观、场景、知情边界及时间线使用现有 `db/persons.md`、`db/settings.md`、`db/scenes.md` 和分段 `summary`；规划见分段 `outline` 与总纲，不能当成正文事实。不另建重复的 `.novel/characters/` 或 `.novel/worldbuilding/` 档案。
- 独立规则库为本文件；报告及历史趋势依据为 `temp/quality-reports/` 中的报告，索引维护于该忽略目录的 `README.md`。这替代技能默认的 `.novel/skills/`、报告和趋势存储位置，不免除任何内容检查；其他机器没有这些本地报告时，不声称读过历史报告。
- 技能所提微逻辑卡、逻辑矩阵、切片、front matter 等专用产物，本项目未采用时须在报告中说明，以现有摘要中的场景、时间、人物知情与衔接记录核对相同问题；不得假称执行过不存在的脚本或把不适用当作跳过逻辑检查。正文不为质检插入说明性旁白或遗留 HTML 注释。
- 评分是模型的编辑判断，不是独立客观检测或用户定稿。未执行 `novel-review` 时不得声称完成双重审稿，也不得仅凭本技能分数将稿件标为最终定稿。技能无法读取或必要资料缺失时，说明阻碍，不绕过检查直接交付为已完成。

## 用户写作约束

### 人物与登场

- 前期以家人和两至三个核心小伙伴为中心；必要的既有老师、工匠可持续参与，但不借此不断扩大核心圈。
- 新人物必须由具体事件和因果关系引出。具名角色出现前明确事件为何需要此人、如何进入场景，以及之后与已有角色的持续关系。
- 降低新人频率，优先发展既有人物的关系、矛盾、合作和变化；禁止“一章一个重要新人”及连续偶遇天才。
- 可以在合理的课堂、工作或共同出行中成组登场，用行动区分人物，避免排队报姓名和履历。
- 已铺垫人物登场须衔接原身份和关系，尤其不能把已有女教师无铺垫替换成另一位老师。
- 不必给所有摊贩、同学、客人和群众命名，也不借背景人物不断添加长期支线；核心伙伴规模不限制背景儿童数量。

### 叙事与成长

- 本书是程序员穿越、中世纪欧洲风格、中魔世界的成长与工坊经营爽文。失败应带来知识、关系或成果，避免连续苦难；技术进步须带来生活、战斗、收入、地位或同伴认可上的可见回报。
- 用问题、实验、结果和人物反应解释机制，避免术语讲义。程序员类比主要用于男主内心和工作文档；当地人使用术节、术式、刻印、运行核心等本地表达。
- 语言要顺口，避免反复用“这一次……”转场、“先……再……这样才能……”讲步骤，或“那就用你最……的……”式对白。不加入“吃了不烧心”“先立规矩”等与场景无关的俏皮话、说教或抽象感慨；保留确有语义作用的正常用词，不机械按词删除。
- 润色时检查说明书式对白、替人物解释情绪的旁白、相邻段落或章节重复的动作与结论。让人物围绕眼前的事说话，兼顾长短句与动作衔接；不为去除模板而堆砌新比喻、方言、肢体反应或额外情节。使用 `novel-humanizer` 时，人物、场景与事实仍以现有 `db/` 为准，报告放入被忽略的 `temp/quality-reports/`，不另建重复的 `.novel/` 档案；主观评分不等于客观检测或用户定稿。
- 对白保留人物当下的疑惑、回忆、犹豫、亲近和随口解释的语气，不把信息拆成整齐的说明条目。日常交谈允许自然的重复、转折、语气词和稍长的句子；不把简短等同于口语，也不靠每句添加“啊、嘛”冒充情绪。母亲被问到习以为常的咒语时，应像在与孩子聊天，而非报告知识边界。
- 不替人物整理对白。对话允许省略、含糊、跳接和话没说完，不必逐句交代清楚发生了什么，也不在后面补解释把省略填满。能由语境、关系与动作让读者领会的内容就留白；只在确会造成情节或指代误解时补足必要信息。
- 不刻意强调事实。正文不反复确认已经发生的事、声明某件事尚未发生，或紧跟动作与对白解释其含义、成果和限制；让读者从场景中自然领会。事实一致性由写作时核对资料保证，不把核对记录写成旁白。必要的信息随情节交代，不为避免解释而故意制造理解障碍。
- 对白不用“要是／如果你问……我还能……可你问的是……”这类先划分问题、再声明能力边界的句式，也不省去“要是”后照搬同一结构。人物遇到不懂的问题，应顺着当下交谈自然承认、犹豫或提出具体打算，不先列举自己能教什么。语气参考用户示例：“这我还真没办法”，玛莎低头看了看板子，“说实话这个我也没学过，有机会我问问我的老师，或许他有办法……”此例只作对白语气参考，不据此新增人物或登记已发生的请教事件。
- 尊重本地工匠和法师的积累，伙伴应有不可替代的贡献；普通程序员经验不等于材料、制造、军政和人工智能全能。
- 重大突破需核对：前置铺垫、知识与材料、参与者、节省的成本、仍存限制、为何此时实现，以及如何改变人物选择。
- 不将每卷章数、全书章数或字数作为硬指标，以完整写完全书为目标；不为凑篇幅拖长，也不为赶着收卷压缩关键成长。

### 核心机制与禁止漂移

- 前世事故是卡车闯红灯；男主转生普通家庭。多数普通人能使用魔法，能力与熟练程度有差异，不把魔法写成少数人的专属特权。
- 人体只能短时缓冲魔力，不能长期蓄魔；天赋核心是安全通过魔力的带宽。训练和外部器具不能无代价绕过各自的供能、输出及控制限制。
- 带宽允许按已定设定通过长期专门训练与魔药培养提高，不写成终身绝对固定或无限增长；具体数值与培养边界见公共设定。低带宽不等于低智力或低制造天赋。
- 教育分级与院系职责以公共设定为准：学堂教咒文书写，不教魔导器制作、战斗魔法或开展理论研究，学院与国立大学分开；校内友谊战不等于实际参战。新增未来天赋与升学安排不能倒填为已写正文事实。
- 资源、币制、收入、价格与魔力数值以 `db/settings.md` 为准；消耗型魔晶与可充能储魔晶体不得混用。远古能源系统是作者层面的真相，不能直接成为前期人物常识；魔兽不施法、没有魔核。
- 技术发展遵循大纲：临时函数及复用／可重入探索、附魔保存、多重施法与集成法阵、压缩和自动解压、接近尾声的通用运行核心、最终纯魔法 AI。具体先后和交叠按大纲展开，不提前兑现后期能力。
- 复用不等于可重入，保存结构不等于复制能量；压缩节省存储，不等于提高威力、无限容量或无限并发。制造仍依赖材料、精度、隔离和工匠知识。
- 禁止追加系统面板、神赐管理员权限、无限魔力、人体无限蓄魔、复制函数即复制能量等设定；不得提前把短时调度称为最终通用系统。
- 操作系统不自动产生意识；伊恩独立制作的初级助手 AI 没有成长能力，他不能凭自身知识创造 AGI。后期可在古代高级 AGI 帮助下获得自身智能，人形器具方向按公共设定衔接，不用自然进化、灵魂附体或未经确认的意识融合替代。具体帮助机制、外形与身份问题不擅自定案。
